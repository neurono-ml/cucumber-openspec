cucumber-openspec

cucumber-openspec 将 OpenSpec 的 spec.md 文件转换为确定性的 Cucumber / Gherkin .feature 文件。

它使用零 AI、确定性的 TypeScript 脚本——一个状态机解析器与生成器——来生成正确的 .feature 文件，支持全部 80 种 Gherkin 语言。除了 Node.js 外没有其他运行时依赖。

快速开始

# 为你的 AI 代理安装此技能
npx skills add neurono-ml/cucumber-openspec

# 将项目的规范转换为 Gherkin
npx tsx scripts/index.ts -i ./openspec -o ./features

功能特性

  • 确定性解析器——状态机，零依赖
  • 80 种 Gherkin 语言——英语、葡萄牙语、简体中文、阿拉伯语、日语等 76 种语言
  • 标签——@smoke、@regression、@critical，支持功能层、规则层和场景层
  • 背景（Background）——通过 ## Background 章节共享步骤
  • 场景大纲 + 示例（Scenario Outline + Examples）——数据驱动的参数化场景
  • 数据表格（DataTables）——管道表格作为步骤参数
  • 文档字符串（Doc Strings）——子项目符号转换为 """ 代码块
  • 增量规范（Delta specs）——ADDED / MODIFIED / REMOVED 章节用于变更管理
  • Gherkin 语法验证——所有输出通过 @cucumber/gherkin 验证
  • 本地化——通过官方 Gherkin 翻译支持 80 种语言的关键词
  • 智能体技能——可通过 skills.sh 安装，支持 Claude Code、Cursor、OpenCode、Codex

工作原理

OpenSpec spec.md                     →   Gherkin .feature
─────────────────────                    ─────────────────
# [@tag] 领域名称                           [@tag]
## Purpose                                功能：领域名称
## Background                               背景：
- **GIVEN** 步骤                            假如 步骤
### [@tag] Requirement: 名称                  [@tag]
#### [@tag] Scenario: 名称                    规则：名称
- **GIVEN** 文本                                [@tag]
  | 列 | 列 |                                场景：名称
- **WHEN** 文本                                 假如 文本
- **THEN** 文本                                    | 列 | 列 |
                                                   当 文本
                                                   那么 文本

作为智能体技能安装（推荐）

通过 skills.sh 为任何兼容 SKILL.md 的智能体安装：

npx skills add neurono-ml/cucumber-openspec

git clone https://github.com/neurono-ml/cucumber-openspec.git ~/.agents/skills/cucumber-openspec

使用 npm / npx（直接使用）

无需全局安装。项目使用 npx tsx 直接运行 TypeScript：

git clone https://github.com/neurono-ml/cucumber-openspec.git
cd cucumber-openspec

# 安装依赖

使用方法

CLI 参考

npx tsx scripts/index.ts [options]

选项

标志别名描述默认值
--input-i规范文件或 openspec 目录的路径（必填）
--output-o.feature 文件的输出目录./features
--language-lGherkin 语言代码en

输出路径

输入输出
openspec/specs/auth/spec.mdfeatures/auth.feature
openspec/changes/add-auth/specs/auth/spec.mdfeatures/add-auth_auth.feature

示例

转换单个规范文件

npx tsx scripts/index.ts -i openspec/specs/auth/spec.md -o features

生成 features/auth.feature。

转换整个 OpenSpec 目录

npx tsx scripts/index.ts -i ./openspec -o ./features

遍历 openspec/specs/<domain>/spec.md 以及所有 openspec/changes/<change>/specs/<domain>/spec.md 文件。

转换为其他语言

# 葡萄牙语
npx tsx scripts/index.ts -i ./openspec -o ./features -l pt

# 简体中文
npx tsx scripts/index.ts -i ./openspec -o ./features -l zh-CN

# 阿拉伯语（从右到左）
npx tsx scripts/index.ts -i ./openspec -o ./features -l ar

转换增量变更

npx tsx scripts/index.ts -i openspec/changes/add-auth/specs/auth/spec.md -o features

生成带有 ADDED/MODIFIED/REMOVED 注释的 features/add-auth_auth.feature。

标签（Tags）

cucumber-openspec 支持 Gherkin 标签的三个层级：功能层（通过 H1）、需求层（通过 H3 规则）和场景层（通过 H4）。

标签以空格分隔，前缀为 @，支持连字符：@smoke、@regression、@integration-test。

功能层标签

在 H1 标题中的领域名称前添加标签：

# @smoke @regression 认证规范

生成：

@smoke @regression
功能：认证

需求层标签

在 H3 标题中的 Requirement: 前添加标签：

### @critical @slow Requirement: 登录

生成：

  @critical @slow
  规则：登录

场景层标签

在 H4 标题中的 Scenario: 前添加标签：

#### @smoke @regression Scenario: 成功登录

生成：

    @smoke @regression
    场景：成功登录

完整示例

# @smoke 认证规范
## Purpose
认证系统。

### @critical Requirement: 登录
正文内容。

#### @smoke Scenario: 有效凭据
- **GIVEN** 已注册的用户
- **WHEN** 提交有效凭据
- **THEN** 收到令牌

生成的 .feature 文件：

@smoke
功能：认证

  认证系统。

  @critical
  规则：登录
    正文内容。

    @smoke
    场景：有效凭据
      假如 已注册的用户
      当 提交有效凭据
      那么 收到令牌

背景（Background）

Background 章节允许你定义共享步骤，这些步骤将在功能中的每个场景之前运行。

语法

在 ### Requirement: 标题之前使用 ## Background，采用标准步骤语法：

# 认证规范
## Purpose
用户认证和授权。

## Background
- **GIVEN** 用户已登录
- **AND** 拥有管理员角色
- **AND** API 密钥有效

### Requirement: 访问控制
#### Scenario: 管理后台
- **WHEN** 用户访问后台
- **THEN** 看到管理面板

生成：

功能：认证

  用户认证和授权。

  背景：
    假如 用户已登录
    并且 拥有管理员角色
    并且 API 密钥有效

  规则：访问控制

    场景：管理后台
      当 用户访问后台
      那么 看到管理面板

规则

  • 背景必须放置在 ## Purpose 之后、任何 ### Requirement: 或场景标题之前
  • 支持无粗体标记的步骤：- Given 用户已登录（关键词匹配不区分大小写）
  • 背景在每个功能文件中只渲染一次，在所有规则/场景之前
  • 空的背景章节不会产生任何输出

场景大纲与示例（Scenario Outline & Examples）

场景大纲允许你使用占位符和示例表，以不同的数据集运行同一个场景。

语法

使用 #### Scenario Outline: 代替 #### Scenario:，在步骤文本中使用 <尖括号> 表示参数化变量。添加 ##### Examples: 并提供管道表格数据。

### Requirement: 登录
#### Scenario Outline: 不同角色的登录
- **GIVEN** 用户 <role>
- **WHEN** 登录系统
- **THEN** 看到 <dashboard>

##### Examples:
| role    | dashboard      |
| admin   | 管理面板       |
| viewer  | 概览页面       |
| editor  | 内容编辑器     |

生成：

  规则：登录

    场景大纲：不同角色的登录
      假如 用户 <role>
      当 登录系统
      那么 看到 <dashboard>

      示例：
        | role   | dashboard      |
        | admin  | 管理面板       |
        | viewer | 概览页面       |
        | editor | 内容编辑器     |

自动检测

如果在普通的 #### Scenario: 下使用了 ##### Examples:，系统会自动将其提升为场景大纲：

#### Scenario: 登录（自动大纲）
- **GIVEN** 用户 <role>
- **WHEN** 登录
- **THEN** <status>

##### Examples:
| role  | status  |
| admin | 成功    |
| guest | 被拒绝  |

Markdown 表格分隔线

示例表格中的 Markdown 风格分隔行（|---|---|）会被自动跳过。

数据表格（DataTables）

Gherkin 中的 DataTables 提供结构化数据作为步骤参数。在 OpenSpec 中，步骤下方缩进的管道表格会被渲染为数据表格。

语法

- **GIVEN** 系统中存在以下用户：
  | 姓名  | 角色   | 邮箱              |
  | Alice | admin  | alice@example.com |
  | Bob   | viewer | bob@example.com   |
- **WHEN** 管理员检查权限
- **THEN** 用户列表正确

生成：

    假如 系统中存在以下用户：
      | 姓名  | 角色   | 邮箱              |
      | Alice | admin  | alice@example.com |
      | Bob   | viewer | bob@example.com   |
    当 管理员检查权限
    那么 用户列表正确

规则

  • 管道表格必须缩进在其所属的步骤下方
  • 第一行管道行成为数据表格的表头
  • 后续行成为数据行
  • 一个步骤可以有子项目符号（文档字符串）或管道表格（数据表格），但不能同时存在
  • 数据表格支持任何 Gherkin 语言——表格内容与语言无关

对比：文档字符串 vs 数据表格

特性文档字符串数据表格
语法缩进的 - item 行缩进的 `
Gherkin 输出""" ... """`
适用场景自由格式文本、预期输出结构化键值数据、多行数据

文档字符串（Doc Strings）

文档字符串允许你在步骤参数中包含较大的文本块（预期输出、JSON、XML 等）。

语法

在 OpenSpec 中，步骤下方缩进的子项目符号会被转换为 Gherkin 文档字符串：

- **THEN** 系统返回：
  - status: 成功
  - token: abc123
  - expires: 3600s

生成：

    那么 系统返回：
      """
      - status: 成功
      - token: abc123
      - expires: 3600s
      """

实际示例

### Requirement: API 响应
#### Scenario: 成功登录
- **GIVEN** 有效凭据
- **WHEN** 调用登录端点
- **THEN** 响应包含：
  - JWT 令牌
  - 包含姓名和邮箱的用户资料
  - 会话过期时间戳
- **AND** 状态码为 200

生成：

  规则：API 响应

    场景：成功登录
      假如 有效凭据
      当 调用登录端点
      那么 响应包含：
        """
        - JWT 令牌
        - 包含姓名和邮箱的用户资料
        - 会话过期时间戳
        """
      并且 状态码为 200

增量规范（Delta Specs）

增量规范跟踪需求随时间的变化。OpenSpec 支持三种增量章节类型：ADDED（新增）、MODIFIED（修改）和REMOVED（移除）。

增量章节

在 openspec/changes/<change-name>/specs/ 下的变更规范中，使用 H2 标题标记需求组：

# 认证规范
## Purpose
更新后的认证需求。

## ADDED Requirements
### Requirement: 生物识别登录
#### Scenario: 指纹认证
- **GIVEN** 已注册的指纹
- **WHEN** 用户扫描指纹
- **THEN** 授予访问权限

## MODIFIED Requirements
### Requirement: 令牌刷新（之前：1 小时过期）
#### Scenario: 刷新令牌流程
- **GIVEN** 有效令牌
- **WHEN** 令牌即将过期
- **THEN** 返回新令牌

## REMOVED Requirements
### Requirement: 传统令牌支持
功能已移除——所有令牌现在使用 JWT 格式。

生成：

功能：认证

  更新后的认证需求。

  规则：生物识别登录

    场景：指纹认证
      # ADDED
      假如 已注册的指纹
      当 用户扫描指纹
      那么 授予访问权限

  规则：令牌刷新

    # MODIFIED：1 小时过期
    场景：刷新令牌流程
      假如 有效令牌
      当 令牌即将过期
      那么 返回新令牌

  规则：传统令牌支持
    功能已移除——所有令牌现在使用 JWT 格式。
    # REMOVED：传统令牌支持——功能已移除……

输出路径

增量规范遵循特定的命名约定：

输入输出
openspec/changes/add-auth/specs/auth/spec.mdfeatures/add-auth_auth.feature

本地化（Localization）

cucumber-openspec 支持全部 80 种 Gherkin 语言。功能、规则、场景、假如、当、那么、并且、但是、背景、场景大纲和示例等关键词都会根据官方 Gherkin 语言数据自动翻译。

使用方法

# 葡萄牙语
npx tsx scripts/index.ts -i ./openspec -o ./features -l pt

# 日语
npx tsx scripts/index.ts -i ./openspec -o ./features -l ja

# 阿拉伯语（从右到左）
npx tsx scripts/index.ts -i ./openspec -o ./features -l ar

语言头

对于非英语输出，会自动添加 # language: 头：

# language: zh-CN
功能：认证

  背景：
    假如 用户已登录

  规则：登录
    场景大纲：不同角色的登录
      假如 用户 <perfil>
      当 登录系统
      那么 <resultado>

    示例：
      | perfil   | resultado |
      | admin    | 成功      |
      | guest    | 被拒绝    |

从右到左（RTL）语言

自定义语言支持

要添加或验证语言，请查看 gherkin-languages.json 文件。按照官方 Cucumber 格式提交包含新增内容的 PR。
